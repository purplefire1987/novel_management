# ADR-008：WorkBuddy 插件注册与升级策略

- **状态**：已接受
- **批准人**：作者
- **日期**：2026-11-20
- **相关**：ADR-006

## 背景

九 Agent 以 WorkBuddy 专家团插件的形式提供给作者使用。本机客户端不会「读到源目录就生效」，
而是把插件复制到版本化缓存目录，再由 `installed_plugins.json` 指向具体版本。

## 问题

这个机制有一个安静的失效模式：**改了源目录、没改注册表指向，用户仍在跑旧提示词**。

真实案例：专家团从 1.0.0 升到 1.1.0 时，新版本目录被复制进缓存了，
但注册表 `installPath` 没有同步更新，`installed_plugins.json` 里还指向 1.0.0 的路径。
结果实际生效的是 1.0.0，连 `world-architect.md` 都不存在，而没有任何报错。

## 决策

升级必须完成三步，缺一步等于没改：

1. 改源：`plugins/marketplaces/<marketplace>/plugins/<plugin>/` 下的真实文件；
2. 同步缓存：`tar --exclude=.DS_Store` 复制到 `plugins/cache/<marketplace>/<plugin>/<新版本>/`；
3. 改注册表：`plugins/installed_plugins.json` 中该插件的 `installPath` 与 `version` 同时指向新版本。

并且：

- 版本号遵循语义化版本，与系统版本范围绑定（写进插件 manifest 的 `requires`）；
- Agent Prompt 版本与系统版本**分开记录**，Prompt 改了不一定要升系统版本；
- 不覆盖旧插件目录，保留上一版本以便回退；
- 升级前先备份插件目录（`tar -czf`），因为 WorkBuddy 客户端的缓存不可靠。

## 备选方案

| 方案 | 为什么没选 |
|---|---|
| 直接改缓存目录里的文件 | 下次升级会被覆盖，且注册表仍指旧版本，改了等于没改 |
| 用符号链接指向源目录 | 客户端复制时会解引用或直接失败，行为不稳定 |
| 每次升级换插件名（v1/v2 并存） | 作者的专家列表会堆满同名条目 |

## 影响

- 升级是一次三步操作，容易漏第三步——所以写入文档并作为检查项；
- 作者需重启客户端才能加载新版本；
- 若客户端插件机制变更（例如改为动态读取），本 ADR 需重写，
  并且**不得覆盖旧插件目录**，先输出兼容性差异。

## 验收方式

插件安装后，打开任一 Agent 会话，让它报告自己的角色名、可读目录、可写目录；
三项与 `agents/common/permissions.md` 一致才算注册成功。
