# ADR-001：公共仓库与私人 Vault 物理隔离

- **状态**：已接受
- **批准人**：作者
- **日期**：2026-11-20
- **相关**：ADR-004、ADR-005、ADR-010

## 背景

旧系统的形态是「公仓建在库根，私人内容放在子目录 `private/`，靠 `.gitignore` 整目录排除」。
这个形态运行了一段时间，直到一次目录改名（`01_Core_Memory/` → `private/00_Canon/`）暴露了它的失效方式。

## 问题

隔离依赖「清洗清单」与「忽略规则」两处人工维护的列表，而这两处都会在改名、搬迁、新建目录时漏项。
漏项不会报错，只会安静地把私人内容推到公网。

实测后果：3519 个文件在公共仓库上可见三天。发现时已经推送。

## 决策

三个目录物理分离，互不嵌套，一律不使用「父目录 + 忽略规则」形态：

```
<public_repo>    只放代码、Schema、模板、Agent 定义、工作流、文档、虚构示例
<author_vault>   作者私人事实源：Canon、规划、正文、记忆、素材、账本
<runtime>        索引、缓存、日志、staging，可随时删除重建
```

约束落到代码里：

- `novel doctor` 显式检查三者是否互为父子，命中即报错；
- `config.load()` 拒绝把 Vault 解析到公仓内部；
- 所有写入路径经 `ensure_inside(child, vault)` 校验，`..` 与符号链接逃逸一律拒绝。

## 备选方案

| 方案 | 为什么没选 |
|---|---|
| 公仓在库根、私人在子目录 + `.gitignore` | 已实测失效：改名即漏，且漏了不报错 |
| 公仓与 Vault 同一目录、用两个 Git 仓库（`.git` 与 `private/.git`） | 一个目录只能有一个 `.git`；父仓的 `git add -A` 仍会把私人文件收进去 |
| 用一个仓库 + Git LFS 分仓 | 依赖远端配置正确，且历史仍含私人内容，泄露面没有变化 |
| 全部本地、不建公仓 | 放弃了代码复用与版本管理，且无法与 WorkBuddy 端协作 |

## 影响

- 好消息：隔离变成结构约束，改名不再影响边界；`doctor` 能在第一次运行就发现错位。
- 代价：作者要记住三个路径；备份脚本必须覆盖两处（Vault + Runtime 可选）；机器上多一个目录。
- 遗留：旧公仓的历史清洗是独立议题，不在本 ADR 范围（见 ADR-005）。

## 验收方式

`tests/security/test_path_escape.py` 覆盖 `..`、绝对路径、符号链接三种逃逸；
`novel doctor` 在 Vault 落在公仓内时返回非 0。
