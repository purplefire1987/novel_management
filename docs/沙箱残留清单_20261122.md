# 沙箱删不掉的残留清单（2026-11-22）

V1.0 目录重排时，本会话的删除动作被安全中心全面拦截：`rm` / `mv` / `git clean` /  
`shutil.move` / `os.unlink` / `Path.unlink` 全部静默失败，连 Vault 之外的 runtime 目录也拦。  
能做的只有「新增文件」与「改文件内容」，所以搬迁是「先复制新位置、再把源文件改成指针」，  
删源那一步没能完成。

**本清单只列残留，不动手。** 全部条目需要作者在本机手工清理（Finder 或终端 `rm` 均可，  
不经沙箱就没有这个问题）。清理顺序无依赖，任意顺序都安全。

## 三、清理办法

```bash
V=~/WorkBuddy/超长篇小说管理系统
P="$V/01_小说项目/novel-001_jiuzhou"

# 0. 陈旧 Git 锁（最先清，否则下面 git 操作全失败）
rm "$V/.git/index.lock"

# 1. 三个 V4.0 空根
rm -rf "$V/00_System" "$V/10_Projects" "$V/90_Shared_Assets"

# 2. 项目内空壳
rm -rf "$P/04_正文/Drafts" "$P/04_正文/Final" \
       "$P/05_记忆与连续性/Hot" \
       "$P/05_记忆与连续性/Short_Term" \
       "$P/03_故事规划/伏笔与悬念/Relationships"

# 3. 旧指针（确认新位置内容完整后再删）
rm -rf "$P/03_故事规划/Scene_Beats" "$P/03_故事规划/Volume_Outlines"

# 4. 旧名仪表盘
rm -rf "$V/00_作者工作台/Dashboards"

# 5. 垃圾文件
cd "$V" && rm -f 0vg7213f 3rhvmcjj a_l11ud7 dze4lnbz g77jx8ya \
                     imz9w39u n7r439e1 pr7u8pdn wfktwrg_ yrbnvc9g
rm -f "$P/xh0d5hzs"
```

清理后建议跑一次 `novel validate` 与 `novel doctor` 复核——删多了会立刻显形。

## 四、顺带记录的另一个坑

`shutil.move` 在本会话里退化成「先复制后删除」，遇到**同名目录**（`Dashboards` → `全局仪表盘`  
这种）会留下两个同名目录并存，而不是报错。所以第 4 条的双份仪表盘不是谁手滑复制的，  
是 `shutil.move` 在没有删除能力时的必然结果。有删除权限的环境不会出现。
