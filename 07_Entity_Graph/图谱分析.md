# 图谱结构分析

> 两种看法：**InfraNodus 看形状**（聚类、结构缺口、桥接点），**本页看数字**（可复算、可对比）。
> 数字每次跑 `novel rebuild-index` 后会变；本页记录的是 2026-11-05 的快照。

## 一、在 Obsidian 里怎么看

1. 打开命令面板 → **InfraNodus: Advanced Graph View**（或点左侧图谱按钮）。
2. 搜索框留空是看全库；输入 `tag:#势力` 或 `path:01_Core_Memory/Characters` 可只看一类。
3. 重点看三个东西：
   - **Clusters（色块）**：主题团。团之间如果互不相连，就是剧情上的「两张皮」。
   - **Structural Gaps（虚线缺口）**：插件标出的「应该连但没连」的两团。这里最值得补关系。
   - **Top Nodes / Betweenness**：谁是把两块黏住的关键节点。删掉它，图会不会散。
4. 看完回到本页对一下数字，确认不是插件抽样造成的错觉。

**这张表最要紧的一行是「连通块 344」**。含派生页时看起来是一个 742 个节点的大网，那是因为 `实体分布` 和 `Entity_Index` 这两张自动生成的页把几乎每个实体都链了一遍——它们制造的是「索引感」，不是「关系」。

真实的档案互链只覆盖了 430 个节点左右。剩下的 339 个里，289 个是物品——和「物品 0/333 挂上地图」是同一件事的两面：物品档案基本是孤立的资料卡。

## 三、结论与建议

1. **别把派生页当关系看。** 做结构分析时先排除 `07_Entity_Graph/` 与 `Maps/`，否则结论一定是「很健康」。
2. **物品是最大的孤岛群。** 289 张孤立物品卡里，卷一真正会用到的只有十来件。等作者裁定「物品暂不补地点」之后，这批孤岛会长期存在——可以接受，但要知道这是**主动留白**，不是漏挂。
3. **26 个 WORLD 技能库/表类档案没有入链。** 这些是查阅型资料（技能库、命格表、种族表、推金册），本来就少被正文引用。建议在 [[WORLD-0013_技能体系表|修行体系总纲]] 里加一节「分表索引」，把它们收进去，一次性消掉这一撮孤岛。
4. **6 个势力、6 个人物孤立**，这几个是真问题：要么是还没进卷一的边角设定，要么是漏挂了所属/所在地。名单可在 [[12_Dashboard/看板|看板]] 第七节实时查看。

## 四、复算方法

```bash
# 结构问题逐条清单（含断链、重复 ID、关系悬空）
novel integrity

# 重建索引与两张投影页（会顺带刷新实体分布与关系块）
novel rebuild-index
```

图谱连通性没有进 CLI，因为它是一次性诊断而不是日常约束。需要复算时，规则是：
节点取 `01_Core_Memory/` 与 `05_Story_Assets/` 下所有 `.md`，边取正文里指向节点的双链，
双向计边，然后做并查集数连通块。剔除 `07_Entity_Graph/` 与 `01_Core_Memory/Maps/` 才是「档案之间」的真实连通性。
