# 伏笔规则（唯一出口）

伏笔怎么记、什么时候算回收、什么时候算违约——**只在这页定**。
别的地方（仪表盘、模板、代码注释）只许引用，不许复述；复述必然漂移。

- 数据在哪：`06_Plot_Ledger/Foreshadowing/FORESHADOW-xxxx.md`（一条伏笔一页）
- 怎么看：[[12_Dashboard/Foreshadowing|伏笔账本]]（Dataview 视图，不含规则）
- 谁在执行：`00_System/novel_system/src/novel_system/validators/foreshadowing.py`
  的 `check_transition()`，`novel publish` 之前会拦
- 字段怎么填：[[11_Templates/Foreshadowing|伏笔模板]]

## 状态机

```
planned → planted → hinted → triggered → paid_off
             ↘ abandoned
             ↘ overdue（超窗未回收，系统判定，不是人写的状态）
```

| 状态 | 含义 | 谁能进 |
| --- | --- | --- |
| `planned` | 想好了，还没埋 | 立项时 |
| `planted` | 已埋进正文 | 该章发布后 |
| `hinted` | 又提示过一次（读者二次注意到） | 后续章节再提及时 |
| `triggered` | 触发条件已满足，读者已看破 | 条件成立且正文有据 |
| `paid_off` | 已回收，账已平 | 有回收事件或章节引用 |
| `abandoned` | 主动放弃，不再回收 | 作者裁定 |
| `overdue` | 过了回收窗口还没回收 | **系统算出来的**，不是手填 |

## 四条硬规则

1. **不得跳级正向推进**：只能顺着箭头走，不能 `planted` 直接跳 `paid_off`；
   也不能从 `paid_off` 退回 `planted`（回收了就是回收了）。
2. **回收必须有据**：转 `paid_off` / `triggered` 时，必须能指到事件
   （`EVT-CH-xxxx-xxx`）或已发布章节，空口不算。
3. **窗口是硬约束**：当前章早于 `target_reveal_window.start` 时不得标 `paid_off`；
   晚于 `end` 仍未回收，系统标 `overdue`。
4. **章节比较一律按数值**：`CH-0009` < `CH-0010`，不要按字符串比。

> 规则 1–3 在 `check_transition()` 里是硬拦截（`novel publish` 会失败），
> 规则 4 是实现细节但会导致误判，写脚本时照办。
